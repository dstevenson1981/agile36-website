# Write a PRD

Keep it to ~2 pages. Refuse to draft until problem, user, and success metric are clear.

## Before drafting (force these answers)

1. **Problem** — What user pain exists, and what evidence proves it?
2. **User** — Which segment / role feels it most often?
3. **Metric** — One number that moves if this works, and how you measure it.
4. **Alternatives** — What do users do today instead?
5. **Non-goals** — What adjacent asks are out of scope for v1?

If any answer is "CEO wants it" with no user evidence, dig further or stop.

## PRD outline

1. Problem statement + evidence  
2. Goals & success metrics (baseline → target → window)  
3. Non-goals  
4. User stories / requirements (MoSCoW)  
5. Constraints & dependencies  
6. Rollout + rollback criteria  
7. Open questions  

## Rules

- Outcomes over outputs — a shipped unused feature is waste.
- Say no explicitly; every yes is a no to something else.
- Prefer the cheapest validation before full build.
